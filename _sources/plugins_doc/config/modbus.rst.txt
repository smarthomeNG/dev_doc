Im folgenden sind etwaige Anforderungen und unterstützte Hardware beschrieben. Danach folgt die               Beschreibung, wie das Plugin **modbus** konfiguriert wird. Außerdem ist im folgenden               beschrieben, wie das Plugin in den Item Definitionen genutzt werden kann. [#f1]_ 

Es handelt sich bei diesem Plugin um ein **gateway Plugin**.

**ACHTUNG**: Dieses Plugin ist als develop gekennzeichnet. Es kann daher sein, dass es                  noch nicht sämtliche Funktionen unterstützt oder noch fehlerhaft ist.



Beschreibung
============

Plugin zur Geräte-Anbindung über ModBus an SmartHomeNG


Anforderungen
=============




 - Minimum SmartHomeNG Version: **2.0.0**

Konfiguration
=============


Im folgenden ist beschrieben, wie das Plugin **modbus** konfiguriert wird. Außerdem ist im folgenden beschrieben, wie das Plugin in den Item Definitionen genutzt werden kann.


=========
Parameter
=========


Das Plugin verfügt über folgende Parameter, die in der Datei ``../etc/plugin.yaml`` konfiguriert werden:


adapter
=======


Geräte-Logik über reine Register hinaus: pluggit = Betriebsart-Schalter (modBusBit auf Register 168) und Umschalten auf Handbetrieb vor dem Schreiben der Lüfterstufe

 - Datentyp: **str**

 - Mögliche Werte:

   - 
   - **pluggit**


baudrate
========


Baudrate (rtu)

 - Datentyp: **int**
 - Standardwert: **19200**

 - Mögliche Werte:

   - **1200**
   - **2400**
   - **4800**
   - **9600**
   - **19200**
   - **38400**
   - **57600**
   - **115200**


bytesize
========


Datenbits (rtu)

 - Datentyp: **int**
 - Standardwert: **8**

 - Mögliche Werte:

   - **7**
   - **8**


crontab
=======


Update mit Festlegung via Crontab

 - Datentyp: **str**


cycle
=====


Abfragezyklus in Sekunden: positiv = periodisch, 0 = nur Crontab, -1 = kontinuierlich.

 - Datentyp: **int**
 - Standardwert: **300**

 - Minimalwert: **-1**

host
====


Hostname oder IP-Adresse des Modbus-Geräts bzw. Gateways (tcp, rtu_over_tcp)

 - Datentyp: **str**


invalidate_on_disconnect
========================


Gelesene Items bei Verbindungsverlust im Datenbank-Log als ungültig markieren (Datenlücke)

 - Datentyp: **bool**
 - Standardwert: **False**


parity
======


Parität: N (keine), E (gerade), O (ungerade) (rtu)

 - Datentyp: **str**
 - Standardwert: **N**

 - Mögliche Werte:

   - **N**
   - **E**
   - **O**


pause_item
==========


Item, um die Ausführung des Plugins zu steuern

 - Datentyp: **str**


port
====


TCP-Port (tcp, rtu_over_tcp)

 - Datentyp: **int**
 - Standardwert: **502**

 - Minimalwert: **1**
 - Maximalwert: **65535**

serialport
==========


Serielle Schnittstelle, z.B. /dev/ttyUSB0 (rtu); pyserial-URLs wie socket://host:port sind erlaubt

 - Datentyp: **str**


slaveUnit
=========


Slave-Addresse der zu lesenden Modbus-Einheit

 - Datentyp: **int**
 - Standardwert: **1**


stopbits
========


Stoppbits (rtu)

 - Datentyp: **int**
 - Standardwert: **1**

 - Mögliche Werte:

   - **1**
   - **2**


transport
=========


Verbindung: Modbus TCP, Modbus RTU an einer seriellen Schnittstelle, oder RTU-Telegramme über TCP (serielle Gateways)

 - Datentyp: **str**
 - Standardwert: **tcp**

 - Mögliche Werte:

   - **tcp**
   - **rtu**
   - **rtu_over_tcp**


==============
Item Attribute
==============


Das Plugin unterstützt folgende Item Attribute, die in den Dateien im Verzeichnis  ``../items`` verwendet werden:


modBusAddress
=============


Register Adresse welche gelesen werden soll

 - Datentyp: **num**


modBusBit
=========


Item-Wert ist dieses Bit (0 = niederwertigstes) des gelesenen Werts, als bool; modBusFactor gilt nicht. Schreiben nur über einen Adapter.

 - Datentyp: **int**


modBusByteOrder
===============


Endian.BIG oder Endian.LITTLE

 - Datentyp: **str**
 - Standardwert: **Endian.BIG**

 - Mögliche Werte:

   - **Endian.BIG**
   - **Endian.LITTLE**


modBusDataType
==============


Datentyp vom zu lesenden Register (bit, int16 uint16 int32 uint32 float32 string16 stringNN)

 - Datentyp: **str**
 - Standardwert: **uint16**


modBusDirection
===============


Datenrichtung

 - Datentyp: **str**
 - Standardwert: **read**

 - Mögliche Werte:

   - **read**
   - **read_write**
   - **write**


modBusFactor
============


Faktor mit dem der gelesene Register-Wert multipliziert wird

 - Datentyp: **num**
 - Standardwert: **1**


modBusInvalid
=============


Gelesene Werte (vor modBusFactor), die das Gerät zusätzlich zu den Datentyp-Werten für "kein Wert" verwendet, z.B. [32767]

 - Datentyp: **list**


modBusInvalidValue
==================


Item-Wert, wenn das Gerät "kein Wert" meldet (z.B. 0x80000000 bei int32); ohne Angabe bleibt das Item unverändert. Wird ohne modBusFactor übernommen.

 - Datentyp: **foo**


modBusLookup
============


Werteliste Gerätewert: Item-Wert, z.B. {0: Standby, 1: Manuell}; Schreiben setzt den Gerätewert des Item-Werts. Nicht gelistete Gerätewerte werden unverändert übernommen.

 - Datentyp: **dict**


modBusObjectType
================


Auswahl welcher Objekt-Type gelesen werden soll

 - Datentyp: **str**
 - Standardwert: **HoldingRegister**

 - Mögliche Werte:

   - **Coil**
   - **DiscreteInput**
   - **InputRegister**
   - **HoldingRegister**


modBusRound
===========


Gelesene Werte auf so viele Nachkommastellen runden (0 = ganze Zahl), nach modBusFactor; str-Items erhalten Text mit genau so vielen Nachkommastellen

 - Datentyp: **int**


modBusSunSpec
=============


SunSpec-Punkt statt modBusAddress: <Modell>[:<Instanz>].<Punkt>, z.B. 103.W oder 160.module.2.DCW; Adresse und Skalierung liest das Plugin beim Verbinden vom Gerät

 - Datentyp: **str**


modBusUnit
==========


Slave-Addresse der zu lesenden Modbus-Einheit (Unit aus der plugin-Konfig wird überschrieben)

 - Datentyp: **num**
 - Standardwert: **1**


modBusWordOrder
===============


Endian.BIG oder Endian.LITTLE

 - Datentyp: **str**
 - Standardwert: **Endian.BIG**

 - Mögliche Werte:

   - **Endian.BIG**
   - **Endian.LITTLE**


modbusPoll
==========


Bei true am Item eine einmalige Abfrage aller Register auslösen (auch mit cycle: 0).

 - Datentyp: **bool**
